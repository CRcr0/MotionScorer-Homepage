Scoring driving trajectories: case studies and statistics

Five scorers on the same clips, then the paired statistics behind the method's advantage. Comparator pass FINAL.

The two comparator rows reproduce published recipes, not published models. Neither DriveCritic nor DriveJudge releases a checkpoint (the Hub carries only DriveJudgeBench, a video-QA benchmark). The DriveCritic-style row applies that paper's recipe — tune the backbone, read the score from its text channel; the DriveJudge-style row applies its logic — let a frozen VLM decide, per criterion, whether a rule penalty applies. Neither number should be cited as that system's score.

2. Case studies

The Ideal row is derived, not asserted. The rule scorer is right wherever a hard-safety criterion fires — a collision, a red light, leaving the drivable area or an imminent time-to-collision always deserves its penalty. It is wrong in one situation: charging for slow progress when the scene gives a reason to slow. So the ideal score is the rule's own score with the progress penalty removed, and only where hard safety is clean and the corridor geometry confirms something to stop for. Each cell states which case applies.

Each case is one scene planned three ways. A long-tail case is one where the rule penalises progress while every hard-safety criterion is clean — it is charging for a slowdown it cannot justify. An ordinary case is one where the criteria agree.

4. Statistical evidence for the method

These statistics come from the 847-pair NAVSIM evaluation set, not from the clips above. Five scenes cannot support a significance test, and none is claimed for them. The cases show how the scorers behave; this section is the evidence.

Arms were trained with the same budget on the same seeds, so each row is a paired per-seed difference against this work, not a gap between independently reported means. Lower MAE against the teacher is better; a negative Δ favours this work.
